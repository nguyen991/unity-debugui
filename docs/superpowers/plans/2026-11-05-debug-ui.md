# Debug UI Builder — Kế hoạch triển khai

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package UPM `com.ng.debugui` cho phép dev khai báo debug UI bằng lambda (`DebugUI.Panel(this, "Player", p => …)`) để tester chỉnh và xem giá trị khi game đang chạy, trên máy có chuột hoặc cảm ứng.

**Architecture:** UI Toolkit runtime, dựng hoàn toàn bằng code. Gồm các lớp:
- Facade tĩnh `DebugUI`, các method đăng ký có `[Conditional]` để bị xoá khỏi bản release.
- `PanelRegistry` giữ danh sách panel.
- `DebugBuilder` dựng `VisualElement` và tạo binding.
- `BindingGroup` / `ValueBinding<T>` refresh giá trị, bỏ qua các control đang bị ẩn.
- `DebugUIHost` (MonoBehaviour, `DontDestroyOnLoad`) sở hữu `UIDocument`, `PanelSettings` tạo lúc chạy, và `DebugUIWindow` (tab bar, khung nội dung, nút nổi).

**Tech Stack:** Unity 6000.6 (min 6000.0), UI Toolkit, Unity Test Framework 1.8 (PlayMode), Input System tuỳ chọn.

**Spec:** [docs/superpowers/specs/2026-11-05-debug-ui-design.md](../specs/2026-11-05-debug-ui-design.md)

## Global Constraints

- Package `com.ng.debugui` đặt ở `Packages/com.ng.debugui/`, `"unity": "6000.0"`. Chỉ dùng API và tính năng USS có từ 6000.0.
- Namespace `Ng.DebugUI`. Class facade tên `DebugUI`. Runtime asmdef `DebugUI.Runtime`, test asmdef `DebugUI.Tests`.
- Phụ thuộc bắt buộc duy nhất là `com.unity.modules.uielements`. Mọi code đụng tới Input System phải nằm trong `#if NG_DEBUGUI_INPUT_SYSTEM` (define này đến từ `versionDefines`).
- Project chỉ dùng Input System (`activeInputHandler: 1`). Cấm dùng `UnityEngine.Input`.
- Không dùng reflection, không dùng attribute cho API người dùng, không cần setup scene.
- Khi debug UI đóng: không gọi getter nào. Khi giá trị không đổi: refresh không sinh GC.
- `Panel`/`Remove` mang `[Conditional("UNITY_EDITOR"), Conditional("DEVELOPMENT_BUILD"), Conditional("DEBUG_UI_ENABLED")]`. Define `DEBUG_UI_DISABLED` biến mọi API thành no-op.
- Mọi USS class có tiền tố `ngdbg-`.
- Chạy test: Editor đang mở và được kết nối qua `unity` CLI (xem skill `unity-cli`). Sau khi thêm hoặc sửa file, kiểm tra compile bằng `unity cmd console status` (cờ compile-failure phải là false). Chạy test bằng `unity test --mode PlayMode --filter <Fixture> --output Logs/debugui-tests.xml`.
- Commit kèm các file `.meta` mà Editor sinh ra cho file mới.

## Review Focus

1. **Đăng ký trùng tên** (ví dụ `OnEnable` chạy lại, scene load lại): chỉ có một tab, panel cũ bị thay tại chỗ, không nhân đôi. Test ở Task 3.
2. **Owner bị destroy khi panel của nó đang là tab hiện tại:** tab biến mất, tab đang chọn chuyển sang panel khác, không có exception. Test ở Task 3.
3. **Lambda `build` ném exception giữa chừng:** panel vẫn được đăng ký với các control đã dựng xong, kèm một dòng lỗi, exception được log. Các panel khác không bị ảnh hưởng. Test ở Task 3.
4. **Getter trả về `null`** (`string`, hoặc `Label<T>` với `T` là kiểu tham chiếu): hiển thị `""` hoặc `"null"`, không ném NRE. Test ở Task 2.
5. **Getter của slider trả giá trị ngoài `[min,max]`** (game đặt speed=50, max=20): slider hiển thị giá trị bị kẹp, nhưng **không** gọi setter ghi giá trị đã kẹp ngược vào game. Test ở Task 2.

    - Mỗi lần `Tick()`, nếu `Screen.safeArea` hoặc kích thước màn hình thay đổi, đặt padding cho `Root`. Giá trị là inset chia cho tỉ lệ scale của panel, lấy qua `RuntimePanelUtils.ScreenToPanel`.
    - `internal bool IsOverUI(Vector2 panelPosition)`: `Document.rootVisualElement.panel.Pick(p)` khác null.
  - `public static bool DebugUI.IsPointerOverUI`:
    - Có `NG_DEBUGUI_INPUT_SYSTEM`: lấy `Pointer.current.position`, lật trục y (`Screen.height - y`), đổi sang toạ độ panel bằng `ScreenToPanel`, rồi gọi `IsOverUI`.
    - Không có Input System, không có host, hoặc đang tắt: trả về `false`.
  - Phím tắt: trong `Update`, `#if NG_DEBUGUI_INPUT_SYSTEM`, nếu `Keyboard.current?.backquoteKey.wasPressedThisFrame` thì gọi `Toggle()`.
